Fixed-Point Decimal Benchmark Report

Date: 2026-06-20
Repository: fixdec
Harness: examples/fair_bench.rs

Setup

RUNS=10 ITERS=5000000 CHUNK=1000 cargo run --release --example fair_bench
  • 10 independent runs per library/operation.
  • 5,000,000 operations per run.
  • 1,000 operations per timed chunk.
  • mean ns/op drops the best and worst run when more than two runs are present.
  • p90, p99, and p99.9 are computed over timed chunks.
  • Operands are pre-generated outside timing, and all implementations use the same 256 decimal operand string pairs where possible.
  • Formatting benchmarks use a reused String buffer to isolate formatter cost without per-call allocation.
p99.9 is chunk-level latency per operation inside 1,000-operation chunks. It is not single-operation hardware latency.

Interpretation

  • D64 is the strongest exact decimal option overall in this benchmark.
  • D96 is slower than D64, as expected from wider arithmetic, but still much faster than rust_decimal, fpdec, fixed, and bigdecimal for decimal division in this workload.
  • rust_decimal parses fastest and formats close to D64, but division is much slower.
  • fpdec is competitive for add/sub/mul but slower on division and formatting.
  • fixed I64F64 and f64 are speed references, not decimal correctness references.
  • bigdecimal is useful when arbitrary precision matters more than low latency.
